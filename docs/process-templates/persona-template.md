# Persona Definition Template

Use this template when adding or updating personas in OctoAcme docs.

- Name:
- Role Summary: One-line description of the persona's primary purpose.
- Responsibilities: Bullet list of core responsibilities (3–6 items).
- Typical Interactions: Which roles/stakeholders this persona regularly works with.
- Decision Authority: What decisions this persona can make unilaterally vs. requires escalation.
- Escalation Path: Who to contact when this persona cannot resolve an issue.
- Example Scenarios: Short examples showing how this persona works in practice.
- Notes / Variations: Any team-specific differences or alternate titles.

Example:
- Name: Technical Program Manager (TPM)
- Role Summary: Coordinates integration planning and cross-team delivery.
- Responsibilities:
  - Own cross-team planning and milestone tracking.
  - Maintain dependency and risk register.
  - Run integration readiness reviews.
- Typical Interactions: PdM, PM, Engineering Leads, Release Engineer
- Decision Authority: Can re-sequence non-functional work within a release; scope changes require PdM sign-off.
- Escalation Path: PM → Product Lead
- Example Scenarios: See docs/octoacme-roles-and-personas.md
